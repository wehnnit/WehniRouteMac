# WehniRoute 0.3.1

WehniRoute 0.3.1 is a verification release for the two paths that shipped in 0.3.0 without end-to-end evidence: launching real coding harnesses against WehniRoute inference, and upgrading an installed bundle through the built-in auto-updater.

## Harness verification

Each session below used the launcher and provider configuration generated by the app under `~/Library/Application Support/WehniRoute/harnesses/`. The upstream was a real local Ollama model (`kreefcode-coder-v2.5-7b`) connected through the WehniRoute provider system; no simulated responses were used.

- **Claude Code 2.1.318** — `claude -p` through the generated `ANTHROPIC_BASE_URL` / `ANTHROPIC_AUTH_TOKEN` launcher returned `CLAUDE_WEHNI_OK`. WehniRoute recorded a successful Anthropic Messages request routed to `ollama/kreefcode-coder-v2.5-7b` (1,572 input tokens, 8 output tokens).
- **Pi 1.5.0** — the generated `PI_CODING_AGENT_DIR` catalog resolved `wehni auto`, and a non-interactive session returned `PI_WEHNI_OK`. WehniRoute recorded a successful chat-completions request routed to `ollama/kreefcode-coder-v2.5-7b` (404 input tokens, 6 output tokens).
- **DeepSeek Harness 0.1.0-rc.6** — the generated `DEEPSEEK_BASE_URL` / `DEEPSEEK_API_KEY` / `DEEPSEEK_MODEL` environment produced a real completion through the headless profile. WehniRoute recorded a successful chat-completions request routed to `ollama/kreefcode-coder-v2.5-7b` (8,097 input tokens, 5 output tokens).
- **Codex** — remains wired through an isolated `CODEX_HOME` and was intentionally not launched.

The gateway enforced its local API key during the runs: an unauthenticated request returned HTTP 401, while the generated harness scripts authenticated and reached the real provider.

## Auto-update verification

This release is also the upgrade target for an installed 0.3.0 bundle. The updater checks the public GitHub release feed, downloads `WehniRoute-0.3.1.zip`, verifies the published SHA-256, validates the bundle identifier, version, and ad-hoc signature, replaces the bundle in place with a rollback backup, clears quarantine, and relaunches the new build. Application Support, Keychain entries, provider configuration, and traces are preserved.

## Installation

The app is **ad-hoc signed**, not notarized with a paid Apple Developer ID. On first open from a downloaded zip:

1. Open **System Settings → Privacy & Security**.
2. Click **Open Anyway** under Security.
3. Confirm **Open**.

Alternatively, right-click the app and choose **Open**. This is a one-time Gatekeeper confirmation; auto-updates clear quarantine on the new bundle.
